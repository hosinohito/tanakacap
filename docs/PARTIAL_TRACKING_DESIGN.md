# 部位別送信・更新

2026-09-21。部位別送受信とUI更新間隔を実装。モデル、既存4フレーム法、腕長校正、肩ヨー方式は維持。見た目改善と速度改善は別評価。

## 継続する3課題

1. 顔を横に向けた時に腕・手の追従がおかしくなる。共有推論、顔尺度への依存、送信待ち、受信の一括更新を切り分ける。
2. 手・身体を検出できない時に最後の姿勢で止まる。現状は過去の保持指定に沿う。自然姿勢へゆっくり戻すか、適用部位・待機時間を含め改めて決める。
3. 接近・前傾で肩へ誤ったヨーが出る。顔肩比の閾値内で誤ヨーが出る合成例を確認済み。実人物での原因確定と対策は未完了。

先に1の送受信設計を進める。2・3をこの変更へ混ぜて自動採用しない。

## 目的と非目的

- 有効な部位は、他部位の欠測や後段処理待ちの影響を受けず更新する。
- 推論済み、補正済み、送信済み、Unity反映済みを区別して計測する。
- RTMW3Dの共有推論を部位ごとに重複実行しない。頭・身体の生結果は同時に得られるため、送信分割だけでこの推論時間は短縮しない。
- 最初は単一GPUワーカーを維持し、複数モデルの同時実行やモデル更新頻度削減は導入しない。
- 実写表示の長い明示引数による制限、録画優先検証、原本保護を維持する。

## 部位と送信単位

|状態の単位|値|有効性・依存関係|
|---|---|---|
|頭|pitch/yaw/roll|頭専用モードも同じ状態を使用。表情の有効性と分離|
|顔距離|距離比、根拠の状態|頭・表情の表示から独立。内部の身体用尺度とは区別|
|口|開口、幅、丸み、左右口角、横寄せ等|口の必要点だけで有効性を判断|
|眉|左右内外の値|左右別の有効マスクを持つ|
|まぶた|左右閉じ量|左右別の有効マスクを持つ|
|目線|左右方向、上下方向|虹彩モデル。既存の欠測時カメラ方向復帰を維持|
|胴体|pitch/yaw/roll|顔の表示フラグを全体ゲートにしない。肩補正が必要とする根拠の欠測は別扱い|
|左腕・右腕|肘・手首、前方判定等|左右を独立状態とし、既存の座標系を維持|
|左掌・右掌|向きの基底|腕が最後の姿勢でも、有効な掌は保持中の前腕を基準に反映可能な設計|
|左指・右指|曲げ量|各指の有効マスクを維持|

状態は細かく分けるが、UDPを必ず部位ごとに1通へ分割しない。同じ段階で完成した部位は1通にまとめ、Unityでは各部位を独立更新する。左右腕も同じ通に含められるが片側の欠測で他方を無効にしない。

## 送信側の順序

1. 最新画像へframeIdと取得時刻を付け、人物ROI、共有モデルを1回実行する。
2. そのフレームの不変な生結果を頭・表情・身体補正へ渡す。顔尺度を身体に使う場合は軽い幾何計算を先に行う。
3. 頭・口・眉・まぶた・顔距離の補正が完成したら、その部位を送信する。
4. 身体・腕・掌・指の補正が完成したら、その部位を送信する。実測でこちらを先に処理する方が有利なら3と4は入れ替えられる。全体完了待ちは置かない。
5. 虹彩モデルを実行し、目線を後送する。顔/目の入力不足なら推論を省き、目線のlost状態を送る。他の送信は止めない。

最初の実装は同じフレームで共有推論→軽い補正→部位別送信→虹彩の順に直す。長い補正も互いにブロックしない完全非同期化は次段階。各段の例外は依存部位へerrorを通知するが、GPU障害を無理に継続したりCPUへ暗黙切替したりしない。

## ④ 顔尺度と腕の結合の分離：ユーザー確認まで実装しない

現行body3d.pyは `learn_lengths=False` を骨長学習禁止だけでなくfront_projectionの腕追従禁止にも使う。これを以下へ分離する案とする。

- `can_learn_lengths`：信頼できる顔尺度等がある時だけ既存の骨長学習を許可。
- `can_track_arm`：有効な肩・肘・手首と、利用可能な幾何尺度があれば追従。顔尺度が欠測でも肩尺度または鮮度内の既存尺度を使う余地を残す。
- 尺度の出所、最終有効時刻、校正世代を保持し、推定不足をvalidに偽装しない。
- 肩尺度は肩ヨー/前傾の影響を受けるので、そのまま採用して品質解決と扱わない。顔が横向きになる既存録画で比較し、前後位置・腕長の飛びが出ないことを評価する。
- 初回で尺度も骨長も得られない場合は、その腕だけwarmup/lostとし、表情や他部位を巻き込まない。

送信分割とこの変更は別コミット・別比較とし、効果を切り分ける。

## パケットv2

ヘッダーにversion=2、streamId、packetSequence、frameId、取得時刻、送信時刻、partsを持つ。各partにはid、sampleSequence、state、valuesを持つ。観測frameIdと時刻は同じデータグラム内で共通。指は有効マスクを含む。

- stateはvalid / held / lost / disabled / error。held再送は新しい観測として数えない。
- `parts`に含まれない部位は「今回は更新なし」。falseや0で上書きしない。値0は有効な観測値。
- packetSequenceは診断用。順序採否は部位ごとのsampleSequenceとヘッダーframeIdで判定し、古い目線の到着が新しい腕を巻き戻さない。
- 通常のinvalid/lostは新しい状態更新として通知するが、最終有効観測の時刻を延長しない。
- 現行4096byte受信上限は維持する。最悪サイズをシリアライズして検査し、超える時は部位境界で分割。無効な部位は破棄し他の正常部位を残す。ヘッダー不正なら全破棄。
- 部位は絶対目標値を送る。差分パケットにしないため、UDPが1通欠落しても次の有効観測で復帰できる。

## 再起動・欠測・時刻

- LocalSenderが新しいstreamIdと同一PCの単調時計によるstreamStartedを付ける。受信側は新しい開始時刻のストリームだけへ切り替え、旧ストリームの遅延データを拒否する。UI以外の送信ツールも同じLocalSenderを使う。
- 部位ごとに最新受信時刻・最新有効観測時刻・最終目標・最終表示値を保存する。頭の到着で腕の欠測期限を延長しない。
- held/heartbeatは通信生存を示すだけで、観測鮮度を回復させない。無効状態は変化時に即通知し、定期状態通知でも再掲してUDP欠落に備える。
- 観測遅延は送信時点での経過時間も送る。受信側の単調時計と組み合わせ、遅延した古い観測を到着しただけで新鮮と扱わない。既存QPCを使う診断時刻は別に残す。
- 初期の通信期限は現行0.3秒を基準に部位別判定へ移す。Pythonの0.12秒短期保持、Unityの欠測後の表示方針を混同しない。
- 欠測後の表示は別のLossPolicyへ切り出す。初版はholdを維持し、目線のみ既存のカメラ方向復帰。課題2の自然姿勢復帰は後でこの方針として追加する。

## Unityの変更

- 受信した全体をcurrentへ丸ごと代入せず、PartStateStoreへマージする。
- UnityメインスレッドのLateUpdateで、受信キューを時間/件数上限付きで処理し、各部位の最新状態を1回読む。複数受信で同じ描画フレーム中に何度もボーンを駆動しない。
- 全体tracked=falseによる早期returnを撤去。頭は頭の有効性、腕は左右それぞれの有効性で更新する。顔の親フラグによる口/眉/まぶた/目線の一括抑止も部位判定へ変更する。
- 処理順はルート/接近→胴体→頭→腕→掌→指→表情。親の更新後に子を反映する。既存の前腕キャッシュ移送とローカル姿勢保持を維持する。
- 掌の計算に必要な前腕姿勢がない場合だけ掌を保持する。ArmTracked=falseを無条件に掌/指全体の停止条件にしない。異なるframeIdの腕と掌を混ぜた時の誤回転は検証対象。
- 異なる部位の同時刻到着は要求しない。使用したframeId差と観測年齢を診断に残し、親子のずれを平滑化で抑える。内部の描画目標TrackingPacketへ、部位ごとのホワイトリスト項目だけを合成する。TrackingPacketを直接ネットワーク受信する経路はない。保存済み数値ポーズは内部の検証入力であり、旧通信の互換処理は置かない。
- 描画60/30/自由指定を維持。推論同期は「新しい有効な部位状態が来た」を更新要求にするが、同一フレームの複数パケットはまとめ、送信数倍の描画をしない。欠測目線復帰等の継続アニメーションも停止しない。

## 互換性・表示・切り戻し

- ユーザー指定によりv1受信、v1変換、通信方式の切替オプションは作らない。PythonとPlayerを同時更新する。切り戻しはGitを使う。
- 別方式を追加する新しい指示が来た場合は、その時点で意図を確認する。予防的な互換層・複数実装は増やさない。
- UIの「推論 fps」は処理観測数を維持する。13部位はPlayerで受け取った新しいvalid観測同士の実測間隔を指数平均（係数0.25）し、その逆数を小数1桁のfpsで表示する。通信内部のintervalMsは維持する。通信パケット数やモデル単体時間ではない。
- lost=未検出、held=保持中、stale=更新待ち、disabled=OFF、初回valid=計測中。保持再送で更新速度を高く見せない。部位ごとの状態、最終観測年齢、観測frameIdを開発ログへ記録する。
- 推論同期は同じ観測frameの3群を描画回数へ3重加算せず、最初の到着で描画を要求する。後送された部位は次の描画へ反映。既存の0.1秒周期の継続描画を維持する。

## 実装範囲と確認

- `tanakacap/partial_tracking.py`：v2のみ送信、部位境界で4096バイト以内へ分割。
- `__main__.py`：共有推論→頭/表情/距離を送信→身体補正/送信→虹彩/送信。虹彩には順序変更前と同じ生の顔/頭情報を渡す。
- `TrackingParts.cs`：独立した順序、鮮度、欠測状態、ストリーム再起動、描画目標の合成。
- `AvatarDriver.cs`：部位別の適用判定。掌と指を腕の更新フラグだけで停止しない。顔尺度不足による腕停止は④の実装で最大1秒の尺度保持に変更（下記）。
- UI：頭、前後位置、口、眉、まぶた、目線、胴体、左右の腕/掌/指。頭のみでは他部位をOFF表示。
- デスクトップのtanakacap-test.batから通常アバターの自動キーモードを選択したUIを開き、保存して開始する。開くだけでは撮影しない。開発ログON、実写表示なし。
- 継続診断 `tools/diagnostics/check_partial_tracking.py` は既存録画だけを3モードで再生し、部位テレメトリーを `results/partial-tracking` に保存する。
- `TrackingPartsChecks` はPlayerビルド時に部分欠落、0値、順序逆転、重複、遅延、保持、再起動、破損部位、指マスクを検査する。

④は実装済み。欠測時の自然姿勢復帰、接近時の肩ヨー補正は未実装。今回は通常Playerをビルドし、ZIP作成・公開は行わない。

## ④の実装（2026-09-21）

ユーザーが実装を指示。以下の案を、既存front_projection経路へ実装した。1秒/0.2秒は初回評価値であり、実人物品質の確認済みではない。

| 条件 | 案 |
|---|---|
| 補完の開始条件 | 顔尺度の初期校正と、その腕の骨長校正が完了済み。直近の有効な顔尺度が既存の検証を通っていること。未校正の腕には適用しない。 |
| 保持する値 | 顔が有効だった時の信頼できる幾何尺度と校正骨長。欠測中はどちらも学習しない。 |
| 動かしてよい条件 | 同じ人物を追跡中で、肩・肘・手首が既存の信頼度/画面内/幾何検査を通ること。無効な点から姿勢を捏造しない。 |
| 補完時間 | 最初の比較候補は顔尺度の欠測から最大1秒。最終有効時刻から数え、保持の再送で延長しない。この数値は未検証。 |
| 続行できない場合 | その腕だけ最後の姿勢を保持。顔/目/掌/指の通信は巻き込まない。自然姿勢復帰は別課題。 |
| 顔尺度の復帰 | 既存の校正/観測の有効性を確認して実尺度へ戻す。腕の急変を避ける0.2秒程度の移行を比較候補とする。新しい骨長の短縮は許可しない。 |
| 検証 | 顔の横向き、手を前に出す、顔欠測中の身体の前後移動、1秒以上の欠測、再捕捉。既存録画で通信変更とは別に比較。 |

限界：顔欠測中に本人が大きく前後移動すると固定尺度が実距離と合わなくなる。補完秒数と復帰方法を先に評価し、肩幅の短縮から距離を確定したりモデルZを新たな尺度として採用したりしない。

実装：ArmScaleは有効な顔尺度を保持し、最終有効観測から1秒で期限切れ。復帰は0.2秒の線形移行、移行中も骨長学習を停止。骨長の支持値が両節0.07以上（既存solverの条件）の腕、または明示校正済みの腕だけが欠測中に続行する。肩・肘・手首の既存検査は維持。人物データ欠測/両肩の有効性喪失/0.3秒超の観測間隔/動画ループでキャッシュを無効化。人物ID認識を追加したわけではなく、検出が途切れない人物の入れ替わりは識別できない。腕XYだけ保持尺度へ換算し、胴体・掌の尺度処理は維持。期限切れは最後の姿勢を保持する。

検証：309 Python tests（新規4ケース）、Unity再ビルド・自動キーの人工入力・3モード録画UI連携成功。既存録画5187フレームで左右合計の有効腕更新9086→9430、保持尺度で336更新。更新数は精度ではない。results/arm-scale/report.json。実カメラ/実写表示なし。
