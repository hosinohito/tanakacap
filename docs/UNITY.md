# 2026-09-11 最新の動作変更

現在は重複する平均窓が既定。`tracking-settings.json`の`observation_block:3, observation_stride:1`で1〜3と2〜4の平均を使い、毎フレーム更新する。`3,3`なら下記の旧6フレーム方式、`1,1`なら平均なし2観測へ戻る。変更後は同じバッチで再起動。手首の異常回転の解消はユーザー確認済み。肩・親指・腕の奥行きは再修正後の実人物評価が残る。親指の付け根は元の形を保持する暫定方式になった。

既定は３フレーム平均×２観測の試行。ルートの`tracking-settings.json`の`observation_block`を`3`から`1`に変更して再起動すると、平均化だけ従来方式へ戻る。同じデスクトップ.batを使える。頭・表情・胴体・腕・掌・指に適用。約20Hzの合成入力で確認待ちは50→250msへ増える。体感品質は未確認。

腕は手首まで含む前方制約をPythonとUnityで適用。掌は肘の曲がる面を基準に前腕の回旋を分離し、±180度境界の角度を連続させてから可動域へ制限する。[調査と検証](ARM_ROTATION_RESEARCH.md)を参照。古い「初期ボーン基準の角度を直接制限」という記述よりこの変更を優先する。

欠測・低信頼度・人物不在・通信停止では最後の姿勢を保持し、待機姿勢へ戻さない。部位だけ見失った場合は親ボーンに対する姿勢を保持する。両手の指各3関節の屈曲を追加し、指ごとに2観測確認と欠測保持を行う。横開き・親指の対向動作はまだ忠実に再現しない。掌の2観測確認と可動域制限を維持し、確認後の補間・回転速度を速めた。

デスクトップのtanakacap-test.batをダブルクリックして起動する。最新版の検証記録と制限はHANDOFF.md先頭参照。以下に古い待機姿勢移行・指未対応の記述がある場合は本節が優先する。

# haolan駆動の開発用プロトタイプ

BOOTHのHAOLAN 1.6原本を独立プロジェクトに取り込み、lilToon 2.3.4で表示する。顔は従来の2Dモデルを維持し、身体にはRTMW3D-Xを追加。両者をCUDAで推論し、制御値を127.0.0.1:39540へ送る。ネット上の相手への送信機能ではない。

## 起動

```powershell
.\run-avatar.ps1 -Camera 1
```

アバターウィンドウとカメラ診断プレビューが起動する。診断ウィンドウのQ/Escで終了。アバター側はF1で状態表示切替、F2でデモ動作切替。正面の自然な姿勢でアバター側のCを押すと、胴体回転の基準を取り直す。デモはカメラ追跡の証拠にしない。最大18000計測フレームで終了する。起動スクリプトは標準で--body3dを付ける。

不具合の切り分けには `.\run-avatar.ps1 -Camera 1 -Diagnose -Frames 1200` を使う。正面静止、左腕上げ、右腕上げ、腕を前へ出す、左右ひねり、掌を返す動作を順に試す。診断モードは関節座標・深度・送信制御値を保存するが、Webカメラ画像の録画は行わない。

OBSに試しに映す場合は通常のゲームキャプチャ／ウィンドウキャプチャでTanakaCapを選ぶ。今回OBS側の取得検証はまだ行っていない。透過出力も未実装。

## 現在の限界

- フェーズ1の人物映像での精度比較は未完了。フェーズ2の接続と表示を先行して確認中。
- 顔は133点モデルに含まれる68点から目・口の比率と頭の向きを近似。顔専用モデル、3D推定、個人キャリブレーションは未実装。最高精度の達成やパーフェクトシンク相当ではない。
- 腕はRTMW3Dの相対深度を使用する。画像XYと深度Zは単位が異なるため、肩幅0.36 mの仮定でXYスケールを近似する。単眼の絶対距離・正確な人体寸法は復元できていない。急な関節移動を制限・平滑化し、信頼度が低い腕は個別に無効化する。
- 腕の骨長はアバターの実値を使い、二関節の幾何計算で肘を5〜155度に制限する。肩骨は腕の挙上・前方移動に連動させる。これは鎖骨の独立した観測ではない。衣装・胴体との衝突は未対応。
- 掌の向きはWholeBodyの手首と指の付け根から求め、Humanoidの指ボーンを基準に手首へ反映する。指を個別には動かさない。低信頼度・ほぼ一直線の観測・腕欠測では既定の向きへ戻る。
- 胴体の判定失敗で腕まで止める経路を分離。片側肩が短時間消えた場合、0.5秒までスケールだけ保持し、反対側の観測できている腕を処理する。欠測した腕姿勢を推定済みにはしない。
- 胴体は肩の3D方向から左右回転と傾きを求める。前後傾斜は両腰が画面内で検出された場合だけ使用する。腰が画面外の場合に前傾が動かないのは現段階の制約。胴体の回転を首へ二重加算しない。
- 追跡途切れは0.3秒で待機姿勢へ補間。左右の腕を独立して無効化する。
- HAOLANのvrc.blink_left/rightは変位が極小のため、実変位を確認したウィンク２／ウィンク２右を使用する。将来の汎用変換では手動設定または変位評価が必要。
- VRChat専用などの未解決コンポーネント71個を検証用インスタンスから外し、avatar-inspection.txtへ記録。髪・衣装の揺れ、元のギミックは未実装。汎用変換プラグインではない。
- lilToonで描画できることと、元のUnity/VRC環境と同じ見た目であることは別。照明・材質・半透明の比較は残っている。
- 通常はWebカメラ画像を保存しない。check_live_unityはアバター描画だけを保存する。

## 3D身体経路の検証状況

ユーザーは前版で首がよく追従し、身体が平面固定であることを確認。今回平面固定を置き換えた。21 Pythonテスト、Unity内の腕の極端姿勢テスト、既知の奥行き・胴体回転を送る実描画テストに合格。実カメラからの新パケット受信も確認したが、その短時間テストでは人物追跡はfalseだった。更新版の人物動作精度は次の実使用で確認する。

その後のユーザー評価：前傾は時々、ひねりはほぼなし、左腕が上がりにくい、前方伸展が横へ出る。身体品質は未達。ログにも左腕の有効率の低さが出ている。胴体・腕の一括停止を修正し、掌向きを追加して26テストと実ボーン方向検証に合格したが、上記の根本原因の確定・実人物での改善確認はまだ。数値診断による再現評価を優先する。

RTMW3Dの深度出力は576 binsで、学習設定の深度サイズ288に対応する。画像高さ384で深度を復元する参考実装の計算は使用せず、MMPose公式のinput_size=(288,384,288)に合わせた。身体モデルは学習設定と先頭Convを確認してRGB入力とする。顔の既存入力経路はこの変更に含めない。

## 2026-09-11の診断修正：腕が断続的に跳ねる・掌が動かない

ユーザーの診断記録044941を解析。Zピーク値を信頼度とみなし0.1未満で無効化した処理が、強いXY検出まで切り捨てていた。[MMPose公式RTMPose3Dのデコーダ](https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose3d/rtmpose3d/utils.py)は信頼度にmin(max(X), max(Y))を使用し、Zピークは含めない。身体・掌のZ振幅による閾値判定を撤去し、有限値、XY信頼度、骨長や掌の退化判定は維持した。これは深度の正確さを保証する変更ではない。

同一440フレームの有効数は胴体143→407、左腕40→386、右腕108→402、左掌30→327、右掌90→287。結果はresults/replay-20260911-depth-confidence。32テスト合格。記録由来の異なる2姿勢をUnityへ送り、左右の実手ボーン方向との一致と描画を確認した。修正後の実人物での動きの正確さは未確認。骨長による除外と掌の断続的な欠測は残る。
