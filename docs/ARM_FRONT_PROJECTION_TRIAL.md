# 腕の投影短縮から前方奥行きを復元する試行

2026-09-12。ユーザー指定で実装し、既存録画で比較した。モデルの変更や新規撮影はしていない。後方手首の追跡を捨てる可逆モードであり、全姿勢の精度改善を保証するものではない。

## 方式

- `tanakacap/front_projection.py`。Unityで方向を正規化してアバター骨長に戻す前に、短縮した画像平面上の骨からZを復元する。
- 顔尺度に対応した既存の常時校正（5秒以内10支持・短縮禁止）を使用。校正長は人体実寸の確定値でなく下限として扱う。画像平面の骨長をP、支持長をL、観測Zを±Lへ制限した値をzとし、有効長はmax(L, sqrt(P²+z²))、復元Zの大きさはsqrt(有効長²-P²)。校正途中でも妥当なモデル奥行きを平坦化しない。
- 上腕/前腕のZ符号4通りを比較。手首のZ合計が肩よりカメラ側で、骨ベクトル間の屈曲が155度以内の候補から選ぶ。155度は試行値、完全な人体関節モデルではない。
- 観測モデルZ、前回姿勢、過度な折り畳みを避ける弱い項で候補を評価。モデルZの符号を絶対制約にしない。後方へ出た肘、負の前腕Z、実在する横曲げ姿勢は一律に禁止しない。
- 既存3フレーム平均/stride1の方向確認とXY平滑化を維持。Z評価には確認後のモデル観測を渡し、前回の復元Zを新しい観測として再利用しない。
- 顔尺度が使えない時や校正前は腕を欠測保持し、最後の有効な姿勢で止める。肩/胴体/顔の全体停止へ波及させない。SAMのネイティブXYZ経路には本モードを適用しない。

## 切替と固定範囲

`tracking-settings.json`の`arm_depth_mode`は最新試行`front_projection`。`legacy`で直前の腕処理へ戻せる。CLIも`--arm-depth-mode legacy|front_projection`。省略時はlegacy。

検出モデル、顔/目線/口/胴体の出力は同一。肩ヨーの計算は変更しない。掌/指のアルゴリズムは維持するが、腕の有効性によるゲート・履歴は変わるため、掌/指パケットまで同一とは言わない。Unityの顔との接触回避等はそのまま残るため、復元した座標と最終骨位置は完全一致を保証しない。

- 旧方式を再実行した全パケット差0。新旧の顔/口/目/胴体パケットも一致。

- 復元骨長とそのフレームの有効長の最大差5.6e-17m。手首Zは全復元観測で0以上。これは内部整合性であり正解位置の誤差ではない。

## 修正途中に判明した問題と残件

初期比較では腕の有効性が掌/指履歴に影響し、全手パケット固定の主張が成立しなかったため、固定範囲を訂正した。次に前回復元Zの自己参照を除去。最後に校正下限だけで有効長を決めると、初期の実在する前方Zまで消える問題を修正した。最終はtrial-4であり、trial-1〜3や中止した`results/avatar-videos/front-projection-trial`は納品対象にしない。

袖を肘と誤認するXY、単眼の透視投影誤差、校正長の過大推定、符号候補の誤選択、最大の肘跳びは残り得る。カメラ基準の前方制限であり、胴体が大きく回った姿勢の完全な可動域ではない。実人物での改善確認は未実施。まず同一録画の動画評価を行い、補正を追加し続けることは避ける。
