# 前傾・接近時の肩ヨー補正

2026-09-21、ユーザー承認で通常の `face_ratio` へ①連続補正、②不確かな区間の保持、③正面感度の緩和を実装。瞬き・頭ピッチ推定は対象外。

## 現在の計算

肩幅をS、顔サイズをF、肩線に垂直な顔中心と肩中点の距離をGとする。顔サイズと顔中心は鼻梁・眼端8点から取得する。

- `w = S/F`、`g = G/F`。初期安定観測の距離比をg0、支持最大肩幅比をw0とする。
- 観測幅比は `r = w/w0`。共通短縮を取り除いた幅比は `r_corrected = r/min(1, g/g0)`。
- 顔だけの拡大ではwとgが同じ割合で縮み、補正後の幅比は変わらない。顔肩距離が広がった分は逆補正しない。そうすると、うなずき等でヨーを作ってしまうため。
- 幅比0.95以上は0度。従来の `acos(r_corrected/0.95)`（上限80度）に、幅比0.95〜0.85で0〜1になるSmoothstepを掛ける。正面付近の急な立ち上がりを抑え、0.85以下では従来の角度変換を使う。
- g/g0が0.5未満または1.15超、基準からの頭pitch差15度超、頭yaw25度超、顔の肩線方向ずれが肩幅20%超、顔アフィン残差0.08超／非有限なら直前の受理済み符号付きヨーを保持する。既存の点欠測・信頼度不足も保持。これらは試行境界であり、前傾の確定判定ではない。

学習は従来どおり顔サイズで正規化した肩幅比を5秒内10支持の最大値として保持し、縮めない。学習条件も変更していない。補正後の値を肩幅基準として学習しない。

モデルの首・肩・胴体Zを補正へ追加しない。既存のヨー方向の肘Z、身体更新入口のZ条件は変更していない。4フレーム法、腕・掌・指、顔距離の送信値も不変。

`width_only` と `legacy` の計算は従来のまま。旧face_ratioへ正確に戻す場合は今回のコミットをGitでrevertする。比較用の旧実装を製品へ残さない。

## 検証と限界

317 Python tests成功。顔10%拡大だけの合成入力は旧約16.88度→0度。全体の拡大・ロールに対する不変性、接近と本当の肩短縮の併存、不確かな観測の保持と復帰、肩基準の短縮禁止、正面感度の連続性を検査した。

`tools/diagnostics/check_shoulder_projection.py` で保存済み5187観測を直前実装47e85b2と比較。肩ヨー以外の全packet項目は一致。結果は `results/shoulder-continuous/report.json` と `frames.jsonl`。3モードの録画起動・部位別受信は `tools/diagnostics/check_partial_tracking.py` で検査する。

| 録画の区間名 | ヨー絶対値の95パーセンタイル：旧→新 |
|---|---:|
| 接近・離反 distance_move | 18.74→0.00度 |
| 頭を動かす head_only | 14.91→0.00度 |
| 胴体ひねり torso_yaw | 37.57→31.76度 |
| 最後の静止 end_still | 19.41→1.14度 |

正解角度の測定や実写の目視評価ではない。ヨーが小さくなったことだけで精度向上とは言えない。特に胴体ひねり区間の絶対値中央値は14.04→0.17度に減っており、小さな本当のひねりを抑えている可能性がある。

Gはうなずき・肩すくめ・前傾でも変わる。前傾とヨーが同時に起きたとき、Gの短縮をすべて共通短縮と扱うとヨーを過小評価する。採用式では補正が有効な範囲の顔サイズFが代数的に相殺され、実質的に肩幅と顔肩距離の比へ依存する。奥行きの実測や人体幾何の完全な復元ではない。初期姿勢が正面でない問題、誤った最大幅基準、肘由来の方向誤りは解決していない。

確認はデスクトップの `tanakacap-test.bat`（録画＋自動キーアバター）から「保存して開始」。UI実験タブの肩ヨーは「顔との比率」を選ぶ。Python側だけの変更でPlayerの再ビルドは不要。直前開発版から別PCを更新する場合は `tanakacap/shoulder_projection.py` を同じ場所へコピーする。旧リリースから開発版へ移る場合のPython／Player同時更新要件は別途維持する。ZIP作成・公開は行わない。
