# 左右の手の独立性の調査

2026-09-23。本人・アバターとも解剖学的な右手をロールすると、左手（画面向かって右）もロールする。両手を顔の前の横へ持ってきた姿勢で発生し、左指が動かない症状もある。対象はローカル0.1.3のavatars/avatar.tcapに置かれた改変済みHAOLAN。

## 結論と限界

左右の計算関数は共用するが、手の履歴・角度・送信フィールド・反映先の共有や取り違えは今回の調査では見つからなかった。人工入力では指定アバターの左右が独立して動く。実使用の症状そのものは未再現で、解決済みとはしない。製品コード・信頼度閾値・平滑化・アバター原本は変更していない。

## 処理経路の確認

| 段階 | 共通部分 | 左右を分ける部分 |
| --- | --- | --- |
| モデル | RTMW3D-Xが同じ画像から体・顔・両手を推論 | 手の21点は左91〜111、右112〜132 |
| 座標・腕 | 顔尺度、胴体の基準、幾何計算 | 腕は左5/7/9、右6/8/10。各腕の投影・時間フィルター・保持は別状態 |
| 掌 | palm_basis、PalmFilter.update | states/motionをsideで分離。受理フレーム・平均の履歴をコピー |
| 指 | FingerTracker.update | gateのキーは(side,finger)。角度・有効マスクはループごとに新規作成 |
| 送受信 | LocalSender、TrackingParts | left/rightのpalm/fingers各スロットに限定したフィールドのみ更新 |
| Unity | DriveHand、DriveFingers、DriveArmsWithLoss | Arm、Finger、PoseTransition、ArmRotationFrameを左右別に生成。HumanoidのLeft/Rightを明示 |

点番号は[公式COCO WholeBody定義](https://raw.githubusercontent.com/open-mmlab/mmpose/main/configs/_base_/datasets/coco_wholebody.py)とも照合した。共通モデルの推定誤差や共通の胴体・尺度変化による間接影響まで否定した検査ではない。

## カメラ試験の総合原因調査

ユーザーによるカメラ試験 `results/hand-realtime/20260923T070155-023807Z` はcomplete、901観測。前回と同じロール連動は出ず、反対手のピッチへの影響と左指の追従不良を報告。SPACEの時刻マーカーは0件、実写は保存しない診断のため、実際の握り姿勢の正解と各時刻を完全には照合できない。

確認済み：

- 14,316個の掌/指送信フィールドを部位別frameIdでUnity受信と照合。不一致0、float変換差最大3.79e-6。取り違え・通信による値混線の証拠なし。

### 指の値と解釈

製品の指コードは未変更。モデルは角度でなく133点それぞれのX/Y/Z分布を出す。左21点は91..111、右は112..132。Zは576候補の最大位置kから `(k/288-1)*2.1744869` と復号し、[MMPose公式codec](https://github.com/open-mmlab/mmpose/blob/main/projects/rtmpose3d/rtmpose3d/simcc_3d_label.py)の式と一致する。X/Yは画像のピクセル座標へ戻す。左右点番号と復号式に今回取り違えは見つからなかった。

TanakaCapが顔由来の尺度sで `(-x*s,-y*s,-z)` に揃える。これは単眼の弱透視近似であり、モデルの完全なカメラ座標復元ではない。掌基準は手首→人差し指付け根と手首→小指付け根の外積。中指方向に直交化して単位法線nを作り、左は+n、右は-nを指の曲がる内側と解釈する。

人差し指〜小指では、指の骨を「掌に沿う長手方向」と「内側方向」の2成分に投影しatan2で方向角を求める。付け根は掌からの方向角、PIP/DIPは前の骨との方向角差を-180..180度に戻した値。符号付きのまま4フレーム法へ渡し、7度の不確かさ帯を差し引いて負角を0、最大80/110/90度にする。親指は人差し指へ寄る方向を別計算し、根元の対立運動は推定しない。Unityが正の角度をアバターの指軸に適用し可変速度で追従する。

カメラ試験frame575の左中指は、掌内側ベクトル約(-.137,.018,.990)に対し、手首基準のMCP/PIP/DIP/先端のZが0/-15.10/-15.10/0mm。付け根→PIPが判定した内側と逆側へ向かう。計算は約-32.77/-145.59/-33.67度、送信は0/0/0。PIPを投影なしの3D骨間角として測っても144.22度で、単にatan2が大きな角度を捏造した例ではない。生値と平滑化後は時間がずれる（隣のframe574のDIP送信は43.15度）ので同時刻で直接一対一対応と扱わない。詳細 `results/twist-recovery-20260923/finger-examples.json`。

「座標の復号が公式通り」と「独自の掌基準/符号付きヒンジ推定が実際の握りを表す」は別の検証。既存人工テストは左右独立、屈曲の数学、回転不変性を確認しているが、入力の握り方向自体が実装の符号に合わせて作られており、解剖学的な符号の正しさを独立に保証しない。したがって単純な逆解釈もモデル誤推定も現時点では断定しない。特に今回のカメラ記録には実写がない。左だけ反転/負角の絶対値化は未採用。次は向きが既知の手形状による独立した符号検証と、既存録画の左右反転再推論で推定誤差を切り分ける。両方に問題がある可能性も残る。
