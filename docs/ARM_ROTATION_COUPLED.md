# 肘の曲げと前腕のねじりを分ける

2026-09-21。通常の回転方式を上腕に従属する方式へ変更。旧方式と±90度は、その後[実験UI](UI_EXPERIMENT_AUDIT.md)にも追加。無制限は録画比較専用。推論モデル、入力の関節位置、奥行き復元、IKの目標と前方補正の通常採否は変えない。手の頭回避は引き続きON。

## 基準軸を取得する

原本の上腕・前腕が約5度以上曲がっていれば、骨の配置から曲げ軸を取得する。ほぼ一直線なら、実行時にTransformだけの一時コピーを作り、HumanoidのForearm Stretchを適用して曲げ軸を取得する。左右別。Renderer、Animator Controller、スクリプトをコピーせず、原本・表示中の骨の姿勢を変更しない。今回のアバターでは左右とも一時コピーを使用した。

UnityのHumanPoseHandlerはHumanoid姿勢をTransform階層へ適用するAPIであるため、取得・書き込みは一時階層上で行う。[公式API](https://docs.unity3d.com/jp/2021.3/ScriptReference/HumanPoseHandler.SetHumanPose.html)。取得できない場合は推測した軸を黙って使わず、初期化エラーにする。今回の検証対象以外のHumanoidでの互換性は未確認。

## 毎回の回転

1. 従来のIKから上腕方向uと前腕方向lを求める。
2. 前回の曲げ軸を、上腕方向の変化に合わせて最短回転で移す。
3. uとlの外積から観測曲げ平面を求める。曲げ角5度以下は軸を保持、5〜20度はSmoothstepで信頼を増やす。軸の周回は最短側、変更速度は最大540度/秒。
4. 上腕をuへ向け、取得した曲げ軸を3の基準へ合わせる。
5. 前腕は上腕の回転を継承した「伸ばした肘」の基準から、u→lの曲げだけを加える。原本の世界方向から前腕を独立回転させない。
6. 掌の向きに必要な残りの回転を前腕の長軸回りへ加える。目標の主値が可動範囲内なら、その到達可能な角度を優先する。範囲外の間だけ直前表示角に近い360度別表現を制限し、±180度表記の境目で端点を切り替えない。表示は既存の最大900度/秒のスカラー追従で範囲の内側を通る。制限なしの診断は連続角を維持する。

曲げ平面を速度制限している途中も、IKの方向は維持する。そのため、その短い区間の曲げは取得した固定ヒンジ軸だけの回転ではなく、u→lへの最短の振りになる。位置を固定したまま、急変した観測平面へ即座に完全一致させ、かつ関節回転を連続にすることはできない。この過渡的な折衷を隠さず、動画で評価する。

描画補間は上腕・前腕の方向と曲げ基準を分けて行うため、旧方式と最終骨位置が常に一致するわけではない。掌・指の頭接触も表示姿勢から判定するため、接触の回数や最終位置が変わることがある。比較で固定しているのは入力・IK目標生成・補正設定である。

## 欠測と制限

掌だけ欠測し腕が有効な間は、掌のローカル姿勢と前腕のねじり角を保持する。世界座標へ固定しない。腕も欠測した場合は、従来の0.5秒待機・1秒机上姿勢・0.5秒復帰を維持する。

ねじりの欠測・復帰補間はQuaternionではなく連続したスカラー角で行う。Quaternionの最短補間が±180度を横切って可動範囲の外へ出ることを避ける。通常の前腕ねじり制限は従来と同じ±160度。肘の屈曲5〜155度、手首の振り90度と残りのねじり±40度も維持し、制限値を狭めて新方式の改善に見せない。

以下の診断引数は `--render-replay` と同時にのみ使える。

| 値（--diagnostic-arm-rotation） | 内容 |
|---|---|
| legacy | 直前の独立回転と旧補間を再現 |
| hinge | 新方式、通常と同じ±160度 |
| hinge-90 | 新方式、前腕ねじりだけ±90度 |
| hinge-unlimited | 新方式、前腕ねじり制限だけ解除。他の関節制限は維持 |

体横断補正の一時的なOFFは今回の比較へ入れていない。通常で残すと指定された補正は全てON。旧経路の内側手前方補正は削除済みのまま。

## 検証と動画

`tools/diagnostics/compare_arm_rotation.py --replay <replay.jsonl> --output <新しい出力先>` で4条件を同一packet・時刻・auto-customアバターで描画する。全6本をデコード検査し、DLL・入力・アバター・動画のSHA256を保存する。動画の見た目はユーザー確認。

最終出力は `results/avatar-videos/arm-rotation-coupled-final`。`previous-vs-coupled.mp4` は左が旧方式、右が新方式・同じ制限。`side-by-side.mp4` は制限違いを含む4画面。各901フレーム/30fps/約30秒。`arm-rotation-coupled` は掌のみ欠測保持を追加する前の途中結果で、最終版ではない。

ビルド時に左右対称、屈曲の相対回転、目標方向の維持、伸び切り付近の軸反転防止、曲げ平面の連続性、±180度境界と欠測復帰の制限を検査。実PlayerでHumanoid軸取得、掌のみ欠測時の相対保持、腕全体の欠測・復帰を確認。311 Python tests成功。実カメラ未使用。

新方式でも、入力肘Zの分岐切替や既存の体横断条件を即座に満たす処理は残る。前腕ボーン1本へのねじり集中、補助ボーン、スキニングも未変更。ねじ切れて見える問題の完全解決を数値検査だけでは宣言しない。

新方式の左急回転は減ったが、右は同条件で僅かに増え、±160度の張付きも残る。制限なしでは連続角が数回転分まで進むので通常採用しない。±90度は角度範囲を犠牲にするため、見た目・追従の評価前に通常へ採用しない。新方式の頭接触は147ステップ、残差0。数値は正解姿勢からの誤差ではない。旧方式の比較動画は直前Playerの肘・手首位置と1e-5m未満で一致することを確認した。


## 上限張り付きの修正（2026-09-23）

+160度から到達可能な-80度を+280度と解釈して再び+160度へ制限していた問題を修正。±90/160度・左右方向・30/60/120fpsで復帰、速度、範囲、範囲外の±180度表記跨ぎをビルド時検査。指定アバターの実Playerで901観測再生と既存の動作/欠測復帰検査に成功。詳細は[手の調査](HAND_SIDE_AUDIT.md#上限復帰と指の解釈の再確認)。制限を守るため、+160→-80は範囲内を240度戻る。範囲外を通る120度の最短回転と可動上限の両立はできない。見た目の品質は未確認。旧方式の実験設定は変更しない。
