# 共通映像によるモデル比較：撮影準備

更新（2026-09-12）：実撮影済み。HaMeRはMANO受領後に独立CUDA推論と指だけの固定補正比較まで検証した。ライブ接続は未実装。最新結果はdocs/HAMER_COMPARISON.md参照。以下の撮影準備時点の「HaMeR未実行」「ユーザー撮影待ち」はこの更新で置き換える。SAMも受領し生CUDA推論まで検証済み。身体補正接続は未完了で、docs/SAM_INITIAL_VALIDATION.md参照。

2026-09-12。ユーザーが一括実装と撮影準備を指示。カメラ素材はユーザーが撮影開始を押して取得する。こちらでは合成映像だけで検証した。

## ユーザー操作

1. アバター検証を終了し、同じWebカメラを使うアプリを閉じる。
2. デスクトップの **tanakacap-compare-capture.bat** をダブルクリック。
3. プレビューでおなか〜頭と左右の手が映るように調整し、「撮影開始」を押す。開始前は保存しない。
4. 日本語の案内に従って約3分撮影する。静止、接近、頭だけの上下左右、左右別の顔横グー・パー、胸前の開閉、掌返し、胴体ひねり、腕の前後/交差、画面外/復帰、最後の静止を含む。
5. 「撮影完了」が出たら画面を閉じる。失敗・中断は完了扱いせず、再撮影する。

映像はresults/comparison-takes/日時/camera.avi、実取得時刻・動作ラベルはframes.jsonl、設定/ハッシュ/欠落数はtake.json。音声なし・ローカル保存・外部送信なし。プレビューのみ鏡像、保存映像は反転しない。HuffYUV可逆圧縮、十分な容量を確保する（開始時30GB以上の空きを検査）。名目30fpsの動画時刻ではなく、sidecarの実取得時刻を比較に使う。取得時刻は露光時刻ではない。

## 解析と実装済み範囲

- **tanakacap-compare-analyze.bat** は最新の完了した撮影を選び、既存モデルの比較を実行する。別テイク指定はrun-comparison.ps1 -Mode analyze -Take パス。
- baseline=RTMW-l顔＋RTMW3D身体/手。顔・目線・口・距離の結果、人物領域、元の時刻を共通キャッシュへ保存し、DWPose-l/RTMW-Xの2D対照でも固定する。
- 2D対照は生の点と身体整合検査用の参照を交換する。3D入力は同じ。指や肘の3Dモデルを替えた試験とは呼ばない。
- 推論はCUDA限定、終了時の実行イベントで主要計算のCPUフォールバックがないことを検査。撮影中は推論しない。
- 各候補の補正状態を初期化し、同じ冒頭から再計算する。既存BodyRetarget、頭/口/目線/距離クラスをそのまま使用。コード・データ・Unity制御・設定のハッシュで比較中の変更を検出。
- 出力はresults/comparisons/日時/index.html、report.json、候補ごとのframes.jsonl/summary.json/replay.jsonl。左右各指の有効数・棄却理由・肘相対深度変動・胴体yaw・距離を動作別に集計。
- replay.jsonlは既存tools/smoke_unity.py --replay-fileへ渡せる。これにより後段のUnity実骨監査へ接続する。今回の合成データ再生は実人物精度の証明ではない。
- 処理時間はファイル再生中の参考値。初回ウォームアップも含み、baselineは顔/身体/目線、2D対照は追加2Dだけなので各行の時間を全システム速度として直接比較しない。ライブ同時描画での遅延・負荷試験は別途必要。

## 取得待ち・未完了を区別する

**撮影準備と現行＋2D対照の比較は実装済み。全候補の3D比較はまだ完成していない。**

- SAM 3D BodyとHaMeRはtools/compare_external_model.pyに独立CUDA環境で動かす生出力ワーカーを追加した。公式関数の引数/色順/手の左右反転を確認したが、重みがないためモデル実行は未検証。本体の.venvにはPyTorch等を混ぜていない。
- SAMのMHR骨格/単位、HaMeRのMANO手、信頼度の扱いを実出力で確認した後に共通補正へ接続する。信頼度を架空の1で埋めない。現段階の外部ワーカー出力は生3Dであり、同一補正のアバター比較を実装・検証済みと扱わない。
- ViTPose++はまだ導入していない。WiLoRは利用条件を確認してからの候補。これらを撮影可能な状態の必須条件にしない。
- 現在の共通映像はこれらの取得後にも再利用できる。重み取得のために同じ動作を撮り直す必要はない。

## 必要なモデルの取得

### SAM 3D Body

[Hugging Face公式モデル](https://huggingface.co/facebook/sam-3d-body-dinov3)へログインし、利用条件を確認してアクセス申請する。承認後、モデルリポジトリのファイルをフォルダー構造ごと取得する。主な必要ファイルはmodel.ckpt、model_config.yaml、assets/mhr_model.pt。assets-source/sam-3d-body-dinov3へ配置すると分かりやすい。秘密のトークンはチャットに貼らない。

[公式導入手順](https://github.com/facebookresearch/sam-3d-body/blob/main/INSTALL.md)に基づき、取得後に独立環境と公式コードを用意する。Detectron2等のWindows対応を含む依存確認が必要。今回の撮影機能はこの環境に依存しない。

### MANO / HaMeR

[MANO公式](https://mano.is.tue.mpg.de/)で登録・利用条件確認・モデル取得を行い、MANO_RIGHT.pklをassets-source/manoへ配置する。ユーザー登録が必要なのはこのMANO部分。HaMeRの公開チェックポイントと公式コード/独立環境はその後こちらで用意する。[HaMeR公式](https://github.com/geopavlakos/hamer)の指定するconfig/モデル構造に従う。MANOを第三者配布先から迂回取得しない。

## 検証

- 171pytest成功（初回は編集時の文字コードと試験ディレクトリ不足で失敗、修正後全成功）。可逆コーデックの実画素一致、タイムライン改変拒否、中断拒否、共通顔処理とライブ処理の一致を検査。
- カメラを開かずTkのPPM画像表示成功。実カメラ撮影はユーザーの開始待ち。
- results/comparison-setup/gpu-smoke：合成18frameをbaseline/DWPose-l/RTMW-Xで実CUDA実行しレポート生成成功。RTMW3D/虹彩も含む。無人合成での接続確認で、人物精度・遮蔽精度ではない。
- 既存231438記録621frameの指有効数（親指〜小指）は左203/168/164/145/141、右324/297/291/299/317。左はpalm_basisが1910指判定分。常に配線が途切れているわけではなく、掌基準が成立しない区間が候補。静止/開閉の区間ラベルなし、原因確定や修正済みとは扱わない。

- 保存性能の追加確認：高エントロピー1280×720の合成30frameでFFV1約20.7fpsだったため採用撤回。HuffYUVは約150.5fps、復号後の全画素一致を確認し採用。容量は大きくなる（合成最大寄りで約130MB/秒相当）ため開始時30GB以上の空きを要求する。既存FFV1の合成テイクもmanifest互換で読める。

- results/comparison-setup/unity-replay.png：生成したreplay.jsonlを実Unityが受信・描画することを確認。

- 未撮影で解析用を開いた場合はエラーにせず、tanakacap-compare-capture.batを案内して終了する。
