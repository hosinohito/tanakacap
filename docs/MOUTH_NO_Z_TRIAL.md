# 口輪郭の推定Zを使わない試行

2026-09-13。ユーザーは口のZによる揺れを疑い、Zを外す比較を要求。現行を調べると、`pnp_depthmouth`は口角・弓形・横寄せに推定Zを使用していた。口の開閉・幅・丸さなどは元からXY、頭ピッチはPnPだった。

## 変更と戻し方

既存の`HeadPose`（`head_pose_mode=pnp`）を再利用し、通常起動の試行設定を変更した。新たな補正を重ねたり、全身のZ出力を削ったりしない。

| 対象 | 今回 |
|---|---|
| 頭ピッチ | 採用済みPnPを維持 |
| 左右口角・弓形・横寄せ | 推定Zによる正面化から、PnP姿勢＋固定テンプレートによる正面化へ |
| 口の開閉・幅・丸さ | 既存XYのまま |
| 時間処理・校正・ガンマ・開口時抑制 | 変更なし |
| 追加モーフ強調 | 両動画とも0、追跡は有効 |
| 目・顔距離・胴体・腕・指・揺れ物 | 変更なし |

「Zなし」は**モデルが毎観測出すZを口へ入れない**意味。固定テンプレートの唇深度と顔の向きの補正は残る（`mouth_lip_depth_scale=1.5`）。単なる画像XYへ戻すと、過去の「下向きで口角が上がる」問題を戻す可能性があるため。モデル自体は腕などに必要なZを引き続き推論するので、GPU推論の削減策ではない。

- 現在の試行：`tracking-settings.json`の`head_pose_mode=pnp`、通常test/liveから利用。
- 直前へ戻す：`head_pose_mode=pnp_depthmouth`、または`run-avatar-lab.ps1 -HeadPoseMode pnp_depthmouth`。
- デスクトップ`tanakacap-test-mouth-z.bat`は直前方式。エージェントは実カメラ起動を行わない。
- `depth3d`は頭ピッチまでZにする過去試行なので、今回の戻し先ではない。

## 比較動画

`results/avatar-videos/mouth-no-z/`：

- `face-closeup.mp4`：顔拡大、左mouth-z（直前）、右mouth-no-z（今回）。
- `side-by-side.mp4`：同じ2方式の上半身比較。
- `mouth-z.mp4`、`mouth-no-z.mp4`：各方式単独。

デスクトップ`tanakacap-compare-face.bat`で顔拡大動画の保存先を開く。全4本のデコード検査成功、各方式185.03秒/30fps/5,551描画フレーム/5,187観測。映像の目視評価はユーザーが行う。新規撮影は不要。

比較入力は既存録画から得た`results/comparisons/face-depth-trial/body3d/frames.jsonl`の保存済みXY/Z/信頼度/時刻。現在のコードで両方の口輪郭を再計算し、時間ゲートを通す。口の4制御値とその有効フラグだけを共通の保存済み制御へ差し替え、頭・目・開口・体・腕・指を固定した。最新推論を全編やり直した比較でも、センサー遅延の比較でもない。

| 数値 | 推定Zあり | 推定Zなし |
|---|---:|---:|
| 口輪郭有効観測 | 3,588 / 5,187 | 5,104 / 5,187 |
| 左口角の隣接変化p95 | 0.4075 | 0.3219 |
| 右口角の隣接変化p95 | 0.4296 | 0.2993 |
| 横寄せの隣接変化p95 | 0.2081 | 0.1163 |
| CPU姿勢/口計算平均（最初30観測を除外） | 0.383ms | 0.456ms |

隣接変化は各方式の連続有効観測だけを対象にした制御値の絶対差。共通分母の精度指標ではなく、意図した表情変化も含む。小さいほど正しいとは限らない。弓形p95は両方0で、この録画は細かな表情を網羅していない。ZなしのCPU処理はこの計測では約0.07ms増えており、高速化したと扱わない。頭ピッチの両方式差は全観測0。有効数増加と変化縮小を試行理由とし、見た目の合格は未確認。

再現（保存先は新しいパスにする）：

```powershell
.\.venv\Scripts\python.exe tools/compare_mouth_depth.py --output results/comparisons/mouth-no-z
.\.venv\Scripts\python.exe tools/render_comparison_videos.py --comparison results/comparisons/mouth-no-z --output results/avatar-videos/mouth-no-z
```

結果JSONは両ディレクトリの`report.json`。入力・コード・Player・動画のSHAを保存する。口角強調度0は現Playerの既定値。今回はUnityコード変更なし、既存Playerを使用した。

## 現在の時間フィルター

`observation_block=3 / observation_stride=1`を維持。`ObservationMean`が[1,2,3]→[2,3,4]→[3,4,5]の平均を作る。`DirectionGate`は採用済み値との差の符号が前回と同じで、今回の平均がその方向から大きく逆行していない場合に採用する。口では成分ごとの判定、deadbandは0.015、瞬間的な大変位の無条件採用は無効。

隣接2平均の範囲は4観測だが、起動直後は最初の平均を初期値にする処理があり、微小変化は保持し、0.2秒超の観測間隔や欠測で履歴をリセットする。よって常に4フレームの固定遅延という意味ではない。口閉じでの中立校正・ガンマ・開口時の上げ抑制・Unityでの補間も別に存在する。平均なしの1/1、旧非重複の3/3へ戻す設定も残している。

PnP/推定Z/口輪郭/観測平均の関連38テスト成功。最初のテスト指定は存在しないファイル名で収集0件だったため、実在する`test_observation_blocks.py`へ訂正して実行した。実カメラ・動画目視は未実施。
