# 着席した上半身の前傾による接近（2026-09-12）

ユーザーは全体平行移動ではなく、座ったまま体を倒して近づく表現を希望。既定を `face_distance_mode="seated"` に変更した。

## 前回の停止の原因

最新 `results/20260911T214143-729551Z-rtmw-l-384/frames.jsonl` は634frame中630で距離送信有効。顔尺度成立632、形状棄却2、成立からゲート出力待ち2。取得できた生距離比は0.4634〜1.3361。有効630frame中197は0.75より近く、旧入力の0.75下限で切られた。出力最小は0.75。したがって今回の接近停止は主に旧実装の距離制限であり、ロストだけではない。実際の注視/姿勢の正解映像は未保存。

## 新しい動作

- Pythonの0.75〜1.5クリップを撤去し、顔尺度から得た距離比を共通3平均/stride1ゲートへ送る。FaceScale自体の信頼度・形状・顔向き棄却は維持。
- 起動時の下部Spine（なければChest）からHeadへのベクトルとカメラ軸方向から、顔の接近量に対応する前傾角度を求める。骨盤、下半身、ルート位置・倍率は変えない。
- 距離によるピッチは既存の胴体ピッチに加算せず置換する。上下のSpine/Chestを同じ絶対ピッチへ向け、下部から上半身が倒れる。既存ヨー・ロールと腕の駆動は維持。
- 頭の向きは従来どおりカメラ基準。胴体前傾を頭角度へ二重加算しない。距離欠測なら最後の距離由来前傾を保持、その他の有効部位は追跡を続ける。
- 試行の可動域は後傾25度〜前傾65度。固定腰からの頭の軌道で届かない近さを、全体移動で補わない。実人体の股関節・脊椎を厳密に再構成するモデルではなく、着席表現の近似。角度限界では顔距離を忠実に再現できない。
- Playerの入力防御は比0.34〜2.86（顔尺度モデルの有効域付近）。通常は先に前傾角度の可動域に達する。制限が全くなくなったわけではない。

GUI `Distance` 行で `tracking` / `ANGLE LIMIT` / `HOLD (lost)` / 初期取得待ち / OFF を分け、角度と入力距離比を表示する。Unity snapshotは `seatedLeanDegrees` と `seatedLeanLimited` を記録。

戻し方：`tracking-settings.json` の `face_distance_mode="translate"` で旧全体平行移動と表示側0.75〜1.5制限、`face_distance_enabled=false` で距離反映OFF。入力側ゲート前のクリップは撤去したため旧方式と過渡応答が完全に同一という意味ではない。完全復元用ZIPは `results/checkpoints/before-seated-lean-20260912.zip`。

## 検証

- Python146件成功。比0.5/2.0が旧クリップを受けないことも検査。
- Unityビルドと実Playerの既存motion回帰成功。新しい実骨検査では骨盤位置/向き・ルート位置の不変、頭の前下方軌道、頭のカメラ基準方向、欠測保持を確認。比0.8で頭は約0.184m接近。これは合成入力の描画検査で実人物精度ではない。
- `results/seated-lean/final.log` が最終成功。`near.png` は着席前傾画像を目視確認、`legacy.png` は旧平行移動への切替確認。
- 最初のmotion検査失敗はOFF検査後にテスト自身が再有効化し忘れたため。修正後成功。初回motion.log/タイムアウトを合格として扱わない。
- 顔・視線推論は変更なし。実人物の前傾表現、強いヨーとの組み合わせ、衣服の変形品質は未確認。
