# 目線の上下・横の応答整理（2026-09-13）

上下が動かないという申告に対し、検出から表示までを監査。虹彩位置はどちらも眼幅で正規化しているが、角度風の通信値への係数は横-80/縦60、Player上限は横20/縦12。従来はgain4（最大強調デモでは6）を掛けてハードクリップしていた。同じ虹彩相対変位でも縦が横の1.25倍の正規化感度となり、早く飽和する。

新30秒録画由来の853packet中gazeTracked589。上下の中央値-3.497、10〜90%点-6.234〜1.467。デモgain6で目標が上限を越える割合は横33.6%、縦74.2%。検出値は変化しているが表示目標に変化が残らない経路を確認。これは追跡有効観測のみの割合で、補間後の実描画の張り付き率ではない。正解視線がなく、偏りを個人差・頭姿勢・モデル誤差に分離できない。

通常既定を共通カーブへ変更。x=yaw×gain/20、y=pitch×gain/15、f(t)=t/sqrt(1+t²)、表示目標=(20f(x),12f(y))。同じ眼幅比の変位は両軸で同じ正規化応答となる。小入力の連続性・符号・ゼロを維持し、大入力でも一律に切り捨てない。ただし上限付近は感度が弱く、ノイズや偏りの解決そのものではない。横の応答も変わる。

最大範囲は維持：眼ボーン±20/±12度、シェイプキー100%。独自虹彩キーは横4mm/縦2.5mmであり、幾何的な移動距離まで同じにはしていない。既存作者キーの最大変形や保存デモ原本は変更しない。4フレーム法・有効時補間rate22・欠測時のカメラ方向への復帰は維持。Player `--legacy-gaze-response` で旧ハードクリップへ戻せる。

検出側で残る候補は、正面注視を明示した校正による個人別中立差の補正と、頭角度/まぶた遮蔽ごとの虹彩誤差分析。録画全体の中央値を自動中立として引くと本当の注視方向を消すため採用しない。上下を眼の開口高さで割る方法も、まばたきで倍率が変化するため採用しない。新モデル追加は今回行わない。

比較準備：`python tools/prepare_gaze_response_comparison.py`。入力/監査 `results/comparisons/gaze-response/report.json`、動画 `results/avatar-videos/gaze-response/face-closeup.mp4`、左gaze-legacy/右gaze-soft。両方全強調デモ、同packet。同録画の目線は旧size2d頭角度での検出ゲートを経て保存されたもの。後から頭表示等をPnPへ再計算しているが、目線モデルをPnP条件で再推論した比較ではない。表示差の分離が目的。実カメラ・実写表示・エージェントの動画目視なし。
