# 肘後方姿勢・指屈曲・通常時の口角の見直し

2026-09-12。対象は着席・単眼カメラ・HAOLAN。ユーザーは左右非対称の口を確認済みだが、通常時にも口角が上がり、顔の前で左手の開閉が取れないと報告した。肘についての具体例は、左肩と左腕を後ろ、右肩と右腕を前にし、左手を少し外へ広げ、左肘が後ろへ突き出す姿勢である。

## 結論と適用範囲

実装には手首が前に見えるという推定から上腕の奥行きまで正に反転する経路があった。また、広げた胴体矩形が肩より外側の手まで前方と判定していた。この組み合わせは、今回の正当な後方肘姿勢を壊し得る。まずこの矛盾を撤去した。モデルが最初から誤った肘を出す問題まで完全に解決したとは扱わない。

人体の可動域を使う方向自体は妥当だが、「肘は常に体の後ろ」「カメラ側の肘は逆関節」といった固定条件は採用しない。上腕の姿勢により他の関節の許される姿勢が変わり、同じ画像上の点から複数の妥当な3D姿勢が成立する。[1] 今回は新しい強い角度制限よりも、観測された後方肘を既存補正が反転しないことを優先する。

## 人体構造から区別するもの

胸郭、上腕、前腕、手はそれぞれの座標系を持ち、関節回転は隣り合う座標系の相対回転として記述する。肩の回転、肘屈伸、前腕回内外、手首の回転を一つのカメラ座標の符号で代用できない。Clarkらは左右の上肢について、座標系・回転順序・校正方法を明示している。[2]

本プロジェクトへの推論として、肩が後退して上腕も後方へ向く状態で、前腕を曲げて手を外側・前側へ置く動きは、肘位置と手位置の前後が異なり得る。手の位置だけから上腕の深度を反転する根拠はない。掌を返す回内外を肘の曲がる側の唯一の根拠にすることも避ける。今回、改善済みの掌回転処理は変更していない。

OpenSimの上肢モデルは肩から指まで複数の自由度と筋の作用を扱う。[3] これは人体が独立した点の集合ではないことを理解する参考であり、このモデルを本ソフトへ導入したわけではない。医学的な可動域保証や筋骨格シミュレーションを行ったとも主張しない。

## 肘位置が一意に決まらない理由

肩S、手首W、上腕長L1、前腕長L2を固定し、d=|W−S|、軸u=(W−S)/dとする。到達可能な範囲では、肘は次の円周上に残る。

`h=(L1²+d²−L2²)/(2d)`

`r=sqrt(L1²−h²)`

`E=S+h*u+r*v` （vはuと直交する単位ベクトル）

これは二つの球面の交わりから得られる幾何であり、本実装の分析である。肘屈曲量が同じでもv、つまり曲がる面が違えば肘の位置は変わる。腕をほぼ伸ばすとrが小さくなり、点のノイズから曲がる面を安定して決めにくい。

現在のUnity SolveArmは観測上腕をこの面へ投影して曲がる側を決め、退化時は以前のpoleを使う。5〜155度の既存屈曲範囲はソフト上の制限であり、全身姿勢に依存した人体可動域モデルではない。今回、この範囲を狭めて症状を隠す変更は行っていない。

## 実装した変更

1. 肩より外側の手に、拡大した胴体矩形だけを根拠とする前方判定をかけない。画面内で肩より内側の手を前とするユーザー指定は維持。
2. DepthAssistのUpperInFrontを常にfalseとし、手首前方から上腕を反転する処理を撤去。過去パケットとの互換用Unity引数は残るが、新しい捕捉パケットでは使用しない。
3. 長さによる深度候補選択で、モデル上腕深度が35mm以上ある場合はその符号を反転させない。これは既存の深度信頼目安を使う工学的方針であり、測定精度35mmの保証ではない。
4. 手首を前に保つ補正では上腕を反転せず、骨長を保存する。前腕だけでは届かない場合は上腕後方量をゼロに近づけて整合させる。矛盾する画像のXYと前方条件を同時に完全保存できない場合、XYも変わる。この補正は測定された運動ではない。
5. 外側の手への前方補正を撤去すると、短縮した前腕が従来の最小長判定で停止する例が増えた。常時学習した長さがある場合に、モデルまたは直前観測の深度符号を保って長さを復元する。深度の向きの証拠がなければ正の向きを捏造しない。
6. 5秒内10支持の腕長・短縮禁止、顔距離補正、顔相対肩幅によるヨー量と生の肘深度による方向、画面外の最後の姿勢保持を維持。

## 左手の開閉

従来は近位指骨を掌平面に投影して指の前向き軸を決めていた。MCPを深く曲げると投影が消失したり反転したりし、握りが伸展としてゼロへ切り捨てられる場合がある。これはコードと合成点で再現した不具合である。

投影が短い場合は手首→MCPの掌面成分を参照し、それ以外も同じ参照と逆向きにならないようにする。左右を同じ原理で処理し、MCP 80/89/90/91/100度で屈曲が失われないテストを追加した。親指の別処理、符号付き角度の平均後の不確かさ帯、4フレーム方式は維持する。

実記録の顔付近の自動抽出は点の矩形による近似で、1本目は左24/右6フレーム、2本目は左0/右3フレームしか該当しなかった。これをユーザーの実演区間の正解ラベルと扱わない。今回の修正が左手問題全体を解消したとは判断できない。次の記録には指ごとの停止段階（掌基底・点信頼度・骨長・屈曲面・観測待ち・有効）を追加した。RGBは保存しない。

## 通常時の口角

今回の口角制御値は負にも動いており、単純な左右反転や「常に正の値」の問題ではない。唇中央のomega変形を疑ったが、2本の記録では中央値・95%点ともゼロであり、今回の主因とする根拠はなかった。

HAOLANの通常時の口角を下げるため、実行時の左右CornerDownへ30%の中立補正を入れた。式は、符号付き口角cに対して `100*(max(0,-c)+0.30*(1-|c|))`。c=-1で下げ100%、c=0で下げ30%、c=+1で下げ0%。上げモーフは従来どおりなので、左右非対称と両端の表情を維持する。30%はユーザーの見た目に対する試行値で、測定した解剖学的中立ではない。原本アバターは変更しない。

初期閉口の口角基準が取れるまでは口角制御をゼロにする。自然な唇中央の形を表情として加算しないため、bowにも同じ初期観測の中央値を差し引く処理を追加した。こちらは今回の主因を直したという意味ではない。ユーザー確認済みの左右非対称を維持し、通常顔が笑顔にもへの字にも寄りすぎないかは実評価を待つ。

## 検証と限界

- 入力：20260911T185608-545920Z、20260911T191301-012493Zの各1800フレーム。
- 保存した旧ソースと新ソースを、同じ2本目の記録・同じ初期状態で再計算。腕有効数は左右1215/1210、掌有効数は1067/1144で一致。追跡継続の検査であり、奥行き精度の証明ではない。
- Unity Editor：左右×胸郭ヨー−45/0/+45度で、外側の手と後方肘、骨長、手首終点を保持する合成検査に合格。
- Unity Player：口角の左右モーフ、掌の反転、画面外保持の既存motion検査に合格。再計算した実記録1800フレームもPlayerへ入力して監査出力を保存。
- pytestの結果と最終実行記録はHANDOFFに記載。成果物は `results/elbow-face-research/`。

今後、観測肘自体が前後を取り違える例が残る場合、まず新しい診断と該当姿勢を照合する。その上で胸郭に対する上腕回旋と肘屈曲面を含む姿勢依存priorを検討する。手首や掌の向きだけから曲がる面を固定する処理へ戻さない。学習済み人体priorの導入には配布条件と対象姿勢の別検証が必要であり、今回は導入していない。
