# 腕の投影短縮が横曲げ姿勢になる経路の調査

2026-09-12。ユーザーは手を前後に動かしたとき、横で肘を曲げて手を顔へ寄せる姿勢になり、骨長を当てはめる過程で肘も前に折れると報告。前方のみへ制限する案を質問。今回は読取監査のみ、推論/補正/Unity動作を変更していない。

## 確認した経路

RTMW3DにはZ推定がある。原論文3.2節は単眼Zの曖昧さと3D学習データの場面多様性の不足を課題として挙げる。「前後の腕運動を想定していない仕様」という根拠はない。 https://arxiv.org/html/2407.08634v1

Unity AvatarDriver.csのDriveArm/SolveArmは、上腕aと前腕bを各々正規化し、アバターの骨長を乗じる。人とアバターの体格を合わせるための処理だが、入力が短いXYとほぼゼロZなら、その短縮を奥行きへ戻す前に平面内へ伸ばす結果になり得る。手首ターゲットも正規化後のa*l1+b*l2から作るため、元の2D位置や投影短縮はそこで保持されない。最終IKはこのターゲットと固定長から肘を求め、胸/顔の回避等も別途適用する。

DepthAssistはその手前で長さ由来のZを補うが、前方フラグがない場合はモデルZが35mm未満だと通常の補助を見送る。投影長比85%以上/15%未満や履歴の符号不一致でも補助が働かない場合がある。前方フラグは主に手首が同側肩より内側という画像条件に依存し、外側でも前方へ伸ばせる姿勢を網羅しない。モデルが平面状を出すと、短縮復元が働かずUnityの方向正規化へ進む経路がある。

## 記録監査

tools/audit_arm_foreshortening.pyで既存撮影のarm_depth案内区間を読取監査。入力・制御のframe整合を確認。有効2218区間骨観測のうち、校正長の75%未満に投影され、モデルの骨間Z差が35mm未満の観測は186。腕の深度モードはmodel90、assisted78、front_length_fit18（モードは腕全体であり特定の骨を補った証明ではない）。診断閾値による候補数で、誤推定率ではない。

例：frame4246/time151.7107、右前腕。校正長約0.3130、投影長約0.1295、モデル骨間Z約0.0064。送信後も長さ約0.1294、Z約0.0071、前方フラグfalse。いずれも内部尺度によるm相当で、人体実測ではない。これをアバター骨長へ正規化すると平面方向が優先される。校正長の誤差も別途検証が必要。

結果：results/comparisons/body-three-models/foreshortening-audit.json。元画像foreshortening-4246.jpgも抽出して確認した。袖による関節の隠れがあり、この一枚をユーザー申告の「顔付近で横曲げ」の正解ラベルとはしない。全候補で実映像との姿勢対応、Unity最終骨までの因果検証は未実施。

## 前方のみ案の評価（未採用）

方向性は有効。画像上で短い投影を短い3D骨として扱わず、校正長と投影を一致させるよう奥行きを復元し、曖昧な前後候補を前方へ限定する。弱透視近似では abs(dz)=sqrt(L^2-dx^2-dy^2)。例のL=0.313/投影0.130なら約0.285m相当の奥行きが必要で、6mmでは合わない。ただし校正長と投影尺度の正しさが前提、近距離では透視投影の整合も必要。

「横で曲げた姿勢」を一律に禁止する方法は避ける。本当にその姿勢を取った場合や、肘/手首が袖で誤検出された場合には誤補正となる。短縮の根拠が継続し、2D点と尺度が有効な場合に、画像と整合しない平面姿勢を候補から除外する案。

後方を捨てる対象は手首の作業領域と、曖昧な骨の前後候補を明確に分ける。手首が体の前でも肘がさらに前なら前腕は後ろ向きになり得るため、上腕/前腕のZを両方正へ固定しない。後ろへ引いた動作を前へ伸ばす出力にするか境界で止めるかは別の振る舞いで、今回の問いを一律反転実装の承認とは扱わない。

次の候補は、モデル3Dを絶対の方向として正規化する前に、投影長・校正長・画像再投影・関節制約・前姿勢で肩/肘/手首をまとめて復元する比較実装。後段Unityの別補正で整合が崩れないよう最終投影も評価する。旧方式を残す。まだ実装/人物品質確認は行っていない。
