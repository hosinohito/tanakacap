# 画像幅と推定分布の試行（2026-09-12）

最新改訂：検出率の分母はwidth_eligibilityによる測定対象フレーム。画面外/低信頼/短縮/欠測と、輪郭抽出の失敗を分ける。旧抽出の最新181805記録では左105/1159=9.06%、右315/1261=24.98%。顔尺度を得られないフレームも幅そのものの測定率からは除外しない。全フレーム率を検出器成功率とした旧評価は訂正する。

抽出は探索線が画面外へ出たとき一括棄却せず、画像内部分から両輪郭を探す形へ修正。幅の最大差30%制限も、4断面以上が支持する緩い線形先細りのモデルへ置換した。1断面の外れ値を許容し、急変/不規則な幅は棄却。下記の旧一律制限より本項が優先。新抽出の実検出率/近さ推定精度は未評価で、奥行き駆動はまだ未接続。

同じ物体・同じ向きなら、画像内の大きさはカメラとの距離の手がかりになる。[OpenCVの投影モデル](https://docs.opencv.org/4.12.0/d5/d1f/calib3d_solvePnP.html)では画像座標が奥行きで割られる。しかし腕の向き、袖の変形、背景との境界が同時に変わるので、輪郭幅から近さを一意には決められない。

今回は姿勢の点だけから幅を計算せず、点を探索場所の目安にして元画像の色変化を横断方向に計測する。5断面のうち4以上に左右の境界があり、幅のばらつきが中央値の30%以下なら計測候補とする。幅pixelsと顔尺度で補正した幅を数値記録する。色差45、最低半幅5pxなどは試行値。境界検出はセグメンテーションモデルではなく、柄や影を輪郭と誤る可能性がある。袖と背景が同色なら原則測定不能。短く投影された前腕も計測不能になりやすい。顔尺度なしでは補正幅を出さない。

この計測は-Diagnoseのログ専用で、画像保存も姿勢の強制前進も行わない。実記録で計測が安定し、向きや袖の変形による変化と区別できる根拠を得てから近さ判定を検討する。現在の腕後方化の解決済み機能ではない。

肩の調整は、信頼度の閾値を上げて欠測を増やす方法ではなく、推定分布から座標を取り出す処理を変更した。[公式SimCC3DLabel](https://raw.githubusercontent.com/open-mmlab/mmpose/main/projects/rtmpose3d/rtmpose3d/simcc_3d_label.py)にはDARKによる分布の補間処理が用意される。今回の実装はそれ自体の移植ではなく、最大binの隣接3値に限定した独自log放物線補間。山から±0.5bin以内に限定し、別の山へ平均を取らない。肩/ひじ/腰だけへ適用し、手首/顔/指は維持する。

整数Zの1段は約7.55mm相当（モデル単位、実距離の保証ではない）で、yawゼロ近傍では片ひじ1段で約1.20度変わる。局所補間でこの段差を減らせるが、最大ピーク自体が袖などへ移る問題は残る。最新実記録にはこの幅を超える動きもあり、丸めだけを震えの原因と断定しない。フレームを追加して待つ処理は増やしていない。

検証はresults/width-subbin/summary.json、GPU実行はresults/20260911T180755-607527Z-rtmw-l-384。合成画像・分布での機能検証であり実人物品質の測定ではない。旧記録にはRGB画像や元のSimCC分布がなく、新デコードの旧記録への再適用はできない。以降はbody_decodeに対象Zの整数/補間binを両方記録する。
