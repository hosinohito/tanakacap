# 高速化の候補と評価

2026-09-13。最新ユーザー指定：全部ONを対象にB→C→Dを実装・評価する。A/Eは保留。B/C/Dの結果と採用状態は[FULL_MODE_OPTIMIZATION.md](FULL_MODE_OPTIMIZATION.md)を参照。揺れ物は今後調整しない。通常モデル/補正を固定した基準から一つずつ可逆比較する。

## 実測の基準

RTX4090、既存1280x720録画、Player/OBS/previewなし、30warmup+900測定、ORT traceOFF。通常構成41.145ms：人物検出の推論呼び出し14.968ms、顔5.683ms、体10.228ms、目4.106ms。INFERENCE_BREAKDOWN.mdに結果への参照あり。今回の頭専用autoは8.601ms（p95 11.147ms）、領域3.828ms/姿勢2.339ms。別日時の計測であり、8.601対41.145をUI用の確定倍率にしない。

| ID | 案 | 主な対象と期待 | 品質・実装上の注意 |
|---|---|---|---|
| A | TensorRT/FP16で同じモデルを高速実行 | 人物・顔・体の重い推論を中心に、ネットワークと重みを保って演算を最適化。効果は未測定 | 数値差、非対応演算、エンジン生成時間、GPU/依存版ごとのcacheと配布条件の確認。まず単一モデルでCUDA基準と出力比較 |
| B | GPUへの転送・起動・同期を減らす | I/O Binding、固定buffer、対応可能なモデルのCUDA Graph。小さい演算をCPUが順次起動する待ちを削減できる可能性 | 全演算CUDA、形状/メモリアドレス等の条件を満たす必要あり。今の通常モデルで転送/起動待ちが何msか先に分離。顔/体の依存を無視した並列化はしない |
| C | 人物検出を毎フレーム行わず、追跡中は範囲を更新 | 毎回約15msの人物検出を、例として3観測に1回＋異常時即再検出。通常の顔・体推定は毎回続ける | 範囲の遅れ、急移動、画面外/復帰、別人への切替を比較。検出を省いた観測に古い範囲を無期限で使わない |
| D | 人物検出専用の入力サイズ・モデルを見直す | 詳細な顔・体モデルを維持し、切り出し範囲を見つける部分だけ軽量化 | 小さい人物・腕を広げた時の範囲欠落を検証。頭専用YuNetを全身範囲の代用品とはしない |
| E | 部位ごとの更新頻度を選択可能にする | 頭/顔は高頻度、体や目線は低頻度にして負荷を調整 | 部位の遅れや時間差が増える。既定全ON・品質優先は維持し、利用者が選ぶ軽量オプション向け。見た目の60fps補間で認識回数が増えたとは扱わない |

Cの例で14.968msを3回に1回へ減らすと、その部分だけの平均は約4.99msになり、理論上約10ms/観測の削減余地がある。ただしこれは算術上の見積もりで、ROI追跡費用/復帰の検出増/CPU-GPU競合は含まない。モデル別中央値の加算・減算を全体の実測値としない。30Hzを保証しない。

どの案も同一録画・補正固定の数値とアバター映像で比較し、次に実カメラ+OBSで測る。中央値だけでなくp95/最大間隔、ロスト復帰、入力から表示までの遅延、CPUフォールバックの有無を確認する。今回の小型頭領域検出の追加は自動取得機能を完成させるためで、上記C/Dによる通常構成の高速化を実施したものではない。
