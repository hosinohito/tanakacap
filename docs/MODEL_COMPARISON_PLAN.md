## 固定するものと比較の境界

ユーザー案の「補正を固定してモデルだけ交換」を一次比較に採用する。モデル依存の色順・リサイズ・出力デコードは各モデルの正規仕様に従い、共通の座標・解剖学的左右・関節順へ変換するアダプターまでをモデル側とする。

その後の4観測ゲート、腕長常時校正、前後prior、関節制限、欠測保持、Unity IK/描画、口・目線・距離設定は同一コード・同一設定ハッシュで固定する。各試行の状態はリセットし、同じ冒頭の校正動作を入力する。異なるモデルの校正済み内部値を使い回さず、校正アルゴリズムと区間を固定する。

全モデルに既存補正を無条件でそのまま接続できるわけではない。メッシュ由来の関節位置、ルート相対Z、カメラ座標Z、単位、信頼度の意味が異なる。RTMW3Dの深度スコアと同じ値を他モデルで捏造しない。信頼度を持たないモデルの可視性推定は独立したアダプター仕様として開示し、互換性が検証できなければ共通補正試験へ進めない。生出力も比較し、既存補正との相性だけでモデルの優劣を決めない。

**現在の入力分担**：2D RTMW-lは顔・距離・身体推定との整合検査等。body3d.pyの指入力は3Dのxyz/scores/depth_scores。--modelで2Dだけを変更してもRTMW3Dは残るため、それを指・肘のモデル交換試験とは扱わない。

顔/目線は良好なので身体・手の比較中は既存顔点と虹彩推論を固定。全身モデルの顔点を採用する比較は別枠とし、口や距離へ勝手に混ぜない。

## 候補と順序

| 候補 | 比較対象と狙い | 導入上の違い・優先度 |
|---|---|---|
| 現行RTMW-l 384 + RTMW3D-X | 基準。顔/身体/手の数値と最終出力を保存して比較 | 導入済み。まず左右指の棄却理由と肘深度の生値/補正後/Unity結果を分離 |
| DWPose-l 384 | 2Dの取りこぼし・袖/顔付近の点の比較 | 導入済みなので手軽な対照。3Dの指・肘がこれだけで改善するとは期待しない |
| RTMW-x 384 | 同系統の大型2Dモデルで現行Lとの差を見る | 公式ONNXあり。公表Whole APはL70.1/X70.2、FLOPs17.7G/29.3Gで大幅改善の保証はない |
| ViTPose++-H WholeBody（必要時L） | 異なる構造の2Dモデルで関節・遮蔽を比較 | WholeBody用ヘッド/重みを選ぶ。17点の身体用とは別。公式設定256×192、ヒートマップ変換が必要。公式リポジトリの古い依存環境を本体へ上書きしない |
| SAM 3D Body（DINOv3、ViT-Hは比較可能性を確認） | **胴体・腕・肘の奥行きの主要な対抗候補**。身体/手の3Dを推定 | MHR骨格から共通関節へ変換。重みアクセス申請、Windows/CUDA実行、ライセンス・実測VRAM/時間の確認が先。4090リアルタイム動作は未測定 |
| HaMeR | **左指の停止と握り動作**へ手専用3D推定を比較 | 手クロップ/左右対応、MANO関節変換が必要。MANOは登録と別条件。手首の身体座標位置は既存に固定して指だけ比較する段階から開始 |
| WiLoR | 手の検出と3D再構成を組み合わせた追加候補 | MANO依存。作者記載のモデル条件CC-BY-NC-NDにより配布用途との整合確認が必要。初期の配布向け優先候補からは外し、条件が合えば研究比較 |

公開APは撮影条件・検出器・解像度が違い、そのままこの着席用途の順位にはならない。ViTPose++がRTMWより必ず良いという根拠にも使わない。全候補を同時に導入せず、基準監査→3D身体/手の対抗候補→必要な2D対照の順を基本とする。最初の2D対照は導入済みDWPoseで手早く準備できる。

## 実施手順

1. **顔距離修正を評価し基準を固定**：静止10秒、ゆっくり接近/離反、素早い接近、首だけ上下/左右、手で顔を隠す→復帰。距離揺れと遅れを別々に見る。
2. **現在の停止段階を監査**：左手の生3D指点、各指のconfidence/visibility棄却理由、送信FingerTracked/Flex、Unity反映を並べる。右手開閉では肩/肘/手首の生XYZと補正の分岐を比較。出力配線の不具合ならモデルの精度問題と扱わない。ここでは補正を増やさない。
3. **共通入力セット**：左右別の開閉（顔横と胸前）、掌返し、腕を交差、外側へ引く、肘を固定して手だけ開閉、胴体を左右にひねる、画面外と復帰を含める。照明/袖/距離を固定し、調整用と評価用のテイクを分離する。
4. **同一入力での品質比較**：共通の入力フレーム/時刻/人物領域を順に各候補へ通す。CPU fallbackは禁止。生点・共通補正後・Unity実描画を比較する。人体正解がないZはmm精度を主張せず、方向の誤り/反転回数/固定肘の変動/指の開閉一致/有効率で評価する。
5. **4090での実時間比較**：同じUnity設定で、処理p50/p95、実効更新Hz、VRAM、欠測率、遅延を測る。複数モデルを同時に走らせた重さを単独候補の性能にしない。固定30Hz観測の品質試験と、実時間でフレームを落とした場合を区別する。4観測の実時間幅も併記。
6. **採用判断**：目/口/掌の既知の良好さを保ち、左指/肘/胴体が改善し、実時間負荷を満たすものを部位別に採用。補正の再調整は一次比較を保存した後の別実験とする。

既存frames.jsonlには推定点があり、別モデルを再推論する元画像はない。アバターのOBS録画もカメラ入力の代わりにならない。同一入力比較にはユーザーが指定したローカルのカメラ動画、または明示的に録画する検証素材が必要。今は撮影・保存・アップロードしない。新モデルや素材を未取得のまま比較済みとは記録しない。
