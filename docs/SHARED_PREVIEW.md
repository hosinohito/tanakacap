# 描画共有・自由解像度・プレビュー省略

2026-09-13ユーザー指定。前回の追加案1/2/3を実装する。通常出力はFull HDへ変更。推論モデル・時間補正・揺れ物ソルバーは変更しない。

## 現在の実装

- OBS用RGBA RenderTextureへアバターを1回描画し、同じ画像をプレビュー背景へ合成する。出力側のMSAA4と既存軽量AAを維持し、プレビューで再度AAはかけない。UIはウインドウ側だけ、OBSへ混入しない。
- MainCameraは姿勢/視線の参照にも使われるため有効のまま、共有時のcullingMaskを0にしてアバターを描かせない。プレビューには背景クリアと画像合成の小さな描画コストが残る。
- `-NoPreview` / Player `--no-preview` / F8で画像合成も省略。ウインドウは背景/状態UIだけになり、OBS・追跡・揺れ物更新は継続。F8で復帰できる。ウインドウ最小化を強制する機能ではない。
- デスクトップの`tanakacap-test-no-preview.bat`でも起動できる。通常test/liveは表示あり。
- `-LegacyPreview` / `--legacy-preview`で比較前の独立したプレビューカメラ描画へ戻せる。共有時の描画数は1、旧方式は2。非表示は両方式でプレビューのモデル描画を止める。
- `-OutputWidth N -OutputHeight N` / `--output-width N --output-height N`。既定1920×1080、各64〜4096。幅省略時は高さ×16/9の整数値（上限超過は拒否）。GPUの最大テクスチャ寸法も検査。無効値を黙って別サイズへ変えない。
- アスペクト比は出力カメラへ反映し、プレビュー側は同じ絵を余白付きで表示する。縦FOVは維持、横FOVは比率に応じて変わる。カメラ入力やモデル入力解像度とは別。
- 通常/live/head-only/motionの起動経路は同じ既定Full HDを使う。非記録/無期限の動作は維持する。

## 解像度の選び方

Full HDは1920×1080のOBS配置で余計な拡大縮小を避けやすい。小さく置く場合は1280×720、960×540など実際の配置サイズに近い値を候補にする。720pの画素数はFull HDの約44%、540pは25%だが、全処理時間やGPU負荷がその比率になるという保証ではない。

本経路のGPU描画/Spout転送で「特定の倍数なら大幅に速い」という実測根拠はない。2のべき乗へ丸めて画素数を増やさない。自由指定では偶数幅/高さを無難な候補とするが、本アプリは奇数も拒否せず、後段のOBSエンコード制約とは分ける。任意の全寸法の互換性を保証するものではない。

GPU画像コピー/合成は[Unity Graphics.Blit](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Graphics.Blit.html)を使用。新規外部ライブラリや追加配布依存はない。正常時にCPU画像読み戻しはしない。

## 将来UIと推論上限（実装予定、今回未実装）

口角追加強調度も同じ設定UIへ追加予定。0〜1連続値、既定0、1で以前の強調。[実装済みの設定/API](MOUTH_EMPHASIS_AND_OPTIMIZATION_JKL.md)を使う。口角追跡ON/OFFとは別。

追加指定：UIへ推論速度を表示する。基本は実際に完了した推論の回数/秒（Hz）。描画fpsや受信Hzとは別の値として明示する。処理時間ms/観測を併記する案も残し、計測範囲と入力待ち・上限待機を含むかを明示する。速度制限中の実稼働Hzを潜在的な最大処理能力と呼ばず、ロスト/停止時に最後の高速値を表示し続けない。表示詳細はUI実装時に具体化、現在は未実装。

ユーザー指定で推論モード切替と同じ設定場所へ、描画レート「60 / 推論同期 / 30 / 自由入力」を配置する。固定値/自由入力で推論能力が描画上限を超える場合は、その数値まで推論頻度も抑え、計算を始める前に待機する。計算済み結果を捨てるだけでは省資源化と扱わない。待機中に古いカメラフレームをためず、処理開始時に最新入力を使う。

推論同期は新しい推論結果に応じて描画する予定。固定モードのような数値がないため、同期モードの上限入力の見せ方・上限未指定時の扱い・欠測/停止時の画面や揺れの更新はUI設計時に明記する。描画/推論相互の測定値で上限を下げ続けるフィードバックにしない。現時点で推論上限や可変描画を実装済みと扱わない。既存の全部ON/部位設定・相対負荷「約N倍」の将来表示と併置する。

## 検証

同じ既存録画/全部ON G+I/body3d/pnp_depthmouth/描画60/OBS60で旧二重描画Full HD、共有Full HD、共有非表示Full HD、自由寸法を比較する。映像目視と実カメラは行わず、OBS透過/合成/画像更新/正常終了と性能ログを確認する。

各60秒、安定区間30〜60秒。RTX 4090、既存録画を最大速度で処理、OBS32.2.2は隔離プレビューのみ（録画/配信なし）。

受信は小幅増加したが、GPU使用率は下がっていない。GPU値は各3標本・全アプリを含む全体値で、小差を確実な省電力効果と断定しない。全体処理には推論等が含まれるため描画回数半減を全体負荷半減と扱わない。各1回の短期比較で、正方形は水平視野も違うため解像度だけの公平な速度比較ではない。通常は指定通り共有Full HDを採用。

4条件ともOBSのRGBA・背景合成・画像変化・Player/推論の正常終了を確認。結果は`results/shared-preview-{legacy1080,full1080,hidden1080,square960}`、集計`results/shared-preview-summary.json`。再現は`tools/phase4_soak.py --seconds 60 --video results/comparison-takes/20260911T235327-031115Z/camera.avi --output results/<新規保存先> --inference-mode graph --detector-interval 3`に各オプションを付ける。

実Playerの共有/非表示/正方形の追加合成入力検証を`tools/smoke_unity.py --obs`で実施。`tools/check_preview_pixels.py results/shared-preview-check`でプレビュー画像と出力RGBAから計算した合成画像を照合。全RGB平均差は共有0.161、非表示0.167、正方形0.164（0〜255階調）、p95はいずれも0.334以下。非表示プレビューは全画素背景、Spout側はアバターを含む。色・上下方向・余白の機械検証であり、人体追従の品質評価ではない。画像は抽出された診断結果を数値処理しただけで、エージェントの目視はしていない。

Unityビルド、Python/PowerShell構文、desktop bat生成・引数照合に成功。F8は同じ表示状態切替へ接続済み、実キーボード操作や長時間/実カメラの見た目は未評価。自由解像度の全組合せは未試験。
