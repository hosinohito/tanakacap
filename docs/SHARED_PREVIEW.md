# 描画共有・自由解像度・プレビュー省略

2026-09-13ユーザー指定。前回の追加案1/2/3を実装する。通常出力はFull HDへ変更。推論モデル・時間補正・揺れ物ソルバーは変更しない。

## 現在の実装

- OBS用RGBA RenderTextureへアバターを1回描画し、同じ画像をプレビュー背景へ合成する。出力側のMSAA4と既存軽量AAを維持し、プレビューで再度AAはかけない。UIはウインドウ側だけ、OBSへ混入しない。
- MainCameraは姿勢/視線の参照にも使われるため有効のまま、共有時のcullingMaskを0にしてアバターを描かせない。プレビューには背景クリアと画像合成の小さな描画コストが残る。
- `-NoPreview` / Player `--no-preview` / F8で画像合成も省略。ウインドウは背景/状態UIだけになり、OBS・追跡・揺れ物更新は継続。F8で復帰できる。ウインドウ最小化を強制する機能ではない。
- デスクトップの`tanakacap-test-no-preview.bat`でも起動できる。通常test/liveは表示あり。
- `-LegacyPreview` / `--legacy-preview`で比較前の独立したプレビューカメラ描画へ戻せる。共有時の描画数は1、旧方式は2。非表示は両方式でプレビューのモデル描画を止める。
- `-OutputWidth N -OutputHeight N` / `--output-width N --output-height N`。既定1920×1080、各64〜4096。幅省略時は高さ×16/9の整数値（上限超過は拒否）。GPUの最大テクスチャ寸法も検査。無効値を黙って別サイズへ変えない。
- アスペクト比は出力カメラへ反映し、プレビュー側は同じ絵を余白付きで表示する。縦FOVは維持、横FOVは比率に応じて変わる。カメラ入力やモデル入力解像度とは別。
- 通常/live/head-only/motionの起動経路は同じ既定Full HDを使う。非記録/無期限の動作は維持する。

## 解像度の選び方

Full HDは1920×1080のOBS配置で余計な拡大縮小を避けやすい。小さく置く場合は1280×720、960×540など実際の配置サイズに近い値を候補にする。720pの画素数はFull HDの約44%、540pは25%だが、全処理時間やGPU負荷がその比率になるという保証ではない。

本経路のGPU描画/Spout転送で「特定の倍数なら大幅に速い」という実測根拠はない。2のべき乗へ丸めて画素数を増やさない。自由指定では偶数幅/高さを無難な候補とするが、本アプリは奇数も拒否せず、後段のOBSエンコード制約とは分ける。任意の全寸法の互換性を保証するものではない。

GPU画像コピー/合成は[Unity Graphics.Blit](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Graphics.Blit.html)を使用。新規外部ライブラリや追加配布依存はない。正常時にCPU画像読み戻しはしない。

## 操作UIと推論上限（2026-09-13実装）

操作UIは60/推論同期/30/自由入力と推論開始前の同じ上限、実推論Hz/描画fps/受信Hz、口角調整を実装済み。入力・上限待機を除く推論ms/観測を頭のみと比較し、測定済み整数倍率を表示する。同期は新packetと100ms以上の更新間隔で描画、上限は独立の入力値。相互フィードバックで上限を低下させない。UIの適用は再起動。詳しい仕様・5構成の検証・未達は[操作UI](CONTROL_PANEL.md)。実写表示制限を維持。
